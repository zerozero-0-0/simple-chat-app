# frontend

Next.js (App Router) + TypeScript + Tailwind CSS。

リポジトリ全体の話は [ルートの README](../README.md) にあります。ここは画面と受信の詳細です。

## 起動

```bash
pnpm --dir frontend install
pnpm --dir frontend dev
```

API の宛先は既定で `http://localhost:8000` です。変えるときは `NEXT_PUBLIC_API_BASE_URL`
を設定します。この値は**ビルド時にバンドルへ埋め込まれる**ので、`build` より前に渡します。

バックエンドの許可オリジンは `http://localhost:3000` 決め打ちです。3000 が埋まっていると
Next は 3001 で上がり、その場で API がすべて CORS に弾かれます。そのときは 3000 を空けるか、
`APP_CORS_ORIGINS` を合わせてください。

## 画面

要件どおり 2 つです。

| パス | 画面 | 中身 |
| -- | -- | -- |
| `/login` | ログイン | 名前を入れて入室する |
| `/` | チャットルーム | 発言の一覧と送信フォーム |

`/` はセッションが無ければ `/login` に送ります。戻すのは `401` のときだけです。
それ以外で戻すと、ログイン画面から入り直してまたここへ、を繰り返します。

## 状態と見た目を分ける

**状態と通信は `page.tsx` が持ち、それ以外のコンポーネントは props だけを見ます。**
UI を作り込むときに触るのは後者だけで済みます。

```
app/
  page.tsx            チャットルーム。入室、送信、退出、エラー
  RoomHeader.tsx      部屋名、接続状態、退出ボタン
  MessageList.tsx     発言の一覧とスクロール位置
  MessageForm.tsx     入力欄と送信ボタン
  login/
    page.tsx          ログイン。名前の状態と入室処理
    LoginForm.tsx     入力欄と送信ボタン
```

`MessageList` だけはスクロール位置という DOM の状態を持ちます。見た目に属する
振る舞いなので、`page.tsx` には出していません。

## 受信 (`lib/useMessages`)

**つないでから取り直します。** 初回もつなぎ直しも同じ道を通ります。取っている間に
届いた分は WebSocket からも来て、`id` で 1 通にまとまります。

```
WebSocket を開く
  └ open したら GET /messages で取り直す
       ├ 返った件数が上限と同じなら、カーソルを進めてもう一度
       └ 取れなければ接続を閉じて、つなぎ直しに任せる
  └ 届いたら一覧に混ぜる
  └ 閉じたら少し待って開き直す (500ms → 1s → 2s → 5s)
```

**カーソルは取り直しの応答からしか進めません。** WebSocket が先に運んできた `id` まで
進めると、その手前の取りこぼしを二度と頼まなくなります。持っている一覧の最大 `id` とは
別に「取り直しで埋めた末尾」を覚えています。

待ち時間を最初に戻すのは、取り直しまで成功したときです。接続できた時点で戻すと、
取り直しが失敗し続ける状況で最短間隔の再接続を繰り返します。

一覧は 1 つの部屋を見続ける前提です。別の部屋に移るときは、使う側を `key` で
作り直して一覧ごと入れ替えます。

## 送信

`client_message_id` を採番して送ります。**同じ本文の送り直しには同じ ID を使う**ので、
届いていたのに応答を取りこぼした場合もサーバー側で 1 通にまとまります。
本文を書き換えたら別の発言なので採り直します ([`lib/draft.ts`](lib/draft.ts))。

- `Enter` で送信、`Shift+Enter` で改行。変換確定の `Enter` では送りません
- 上限 (1000 文字) を超えたときだけ「N 文字多いです」を出します
- 応答を待つ間に打ち足した分は消しません
- 送った直後は、読み返している最中でも自分の発言まで移動します

## 文字数の数え方

サーバーの上限は Unicode のコードポイントで数えます。`String.length` は UTF-16 単位なので、
絵文字があるとずれます。数える前に NFC へ揃え、前後の空白も落とします
([`lib/text.ts`](lib/text.ts))。揃えないと、サーバーが受け取れる長さの名前を画面が先に
弾いてしまいます。

## テスト

```bash
# ユニット
pnpm --dir frontend test

# ブラウザを通した E2E
pnpm --dir frontend run test:e2e
```

ユニットは `*.test.ts`、E2E は `e2e/*.spec.ts` と拡張子で持ち場を分けています。

E2E は本番ビルドに対して走らせます。`next dev` にしかない挙動を結果に混ぜないためです。
開発用とは別のポート (フロント 3100 / API 8100) と別の DB を使い、起動のたびに DB を
作り直すので、開発中のサーバーを止める必要はありません。

閉じたポートへの接続が拒否されずタイムアウトする環境 (WSL2 のミラーネットワークなど) では、
起動前の疎通確認で数分待つことがあります。そのときは `E2E_HOST=::1` を渡してください。

E2E は `build` を走らせるので、実行後の `.next` には E2E 用の API 宛先が埋め込まれた
本番ビルドが残ります。そのあと `pnpm start` で動かすときはビルドし直してください。

## 型チェック

```bash
pnpm --dir frontend typecheck
```

pre-commit には入っていません (GitHub Actions では走ります)。`next typegen` が
`LayoutProps` などを生成してからでないと通らないので、スクリプト側でまとめています。

## lib

| ファイル | 中身 |
| -- | -- |
| `api.ts` | API クライアント。失敗は状態を持つ `ApiError` になる |
| `auth.ts` | 入室。`login` を試し、`404` なら `signup` に回す |
| `useMessages.ts` | 受信。WebSocket と取り直し |
| `messages.ts` | 一覧への混ぜ方と、追いかけるかどうかの判定 |
| `draft.ts` | 送り直しに同じ ID を使うための下書き |
| `text.ts` | 文字数の数え方と名前の正規化 |
| `time.ts` | 時刻の表示 |
| `types.ts` | バックエンドが返す形を写したもの |

`types.ts` はバックエンドのスキーマを手で写した唯一の契約です。ずれると `422` になるので、
[`lib/api.test.ts`](lib/api.test.ts) が送るキー名を固定しています。
